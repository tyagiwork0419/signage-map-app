# 0002. 地図表示方式(フロアプラン画像 / 実地図の両対応)

## ステータス
承認済み

## コンテキスト
「地図」は、案件によって以下の2種類がありうる(ユーザー確認済み: 両方に対応する)。

1. イベント会場のフロアプラン画像(座標系を持たないカスタム画像)
2. 実際の地理座標を持つ地図(住所・緯度経度ベース)

この2つを別々のライブラリ・別々のUIコンポーネントで実装すると保守コストが増える。

## 検討した選択肢
- **Leaflet(react-leaflet)を共通基盤にする**
  - `CRS.Simple` + `ImageOverlay` でフロアプラン画像を「座標系のない単純な平面」として表示できる
  - 既定の `CRS.Earth`(EPSG3857)+ タイルレイヤー(OpenStreetMap等)で実地図を表示できる
  - ピン(マーカー)の設置・ドラッグ・ポップアップ等のUIコンポーネントは両モードで共通のまま使える
  - 参照: https://leafletjs.com/examples/crs-simple/crs-simple.html
- **フロアプラン画像用に独自Canvas実装、実地図用にGoogle Maps JS APIを個別導入**
  - 実装・保守が二重になる。Google Maps APIは商用利用で課金が発生し、今回の要件(APIとして地図提供元を指定されていない)にはオーバースペック
- → Leaflet統一を採用

## 決定
- 地図表示は `react-leaflet` に統一する
- 案件(project)ごとに `map_type` カラム(`'image'` | `'geo'`)を持たせ、フロントエンドはこの値に応じて
  - `image`: `crs={L.CRS.Simple}` + `ImageOverlay`(画像はSupabase Storageに保存)、ピン座標は画像ピクセル座標系
  - `geo`: 既定のCRS + タイルレイヤー(初期実装はOpenStreetMapの無料タイルを利用)、ピン座標は緯度経度
  を切り替えてレンダリングする
- ピンの座標を保持するテーブルは、`x`/`y`(image用)と `lat`/`lng`(geo用)を両方持たせ、`map_type` に応じて片方だけ使う(NULL許容)。将来的にモードごとに正規化するかは、実装が進んでから再検討する

## 結果・トレードオフ
- ピン用UIコンポーネントを1系統に保てる。学習コスト・保守コストが小さい
- OpenStreetMapタイルは無料だが、大量アクセス時のレート制限に注意が必要(今回の想定規模では問題にならない見込み)
- ピンのテーブル設計が「片方のカラムセットしか使わない」不完全な形になる点は、将来のリファクタ候補として残す
